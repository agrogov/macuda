Plan M7.4. Two full soft arms (seed 0, seed 1) trained by the shim on the eGPU, then D§10.3.3's gates against the
Python soft arm. Both arms ran to completion (`exit 0`, 0 error lines, **1 h 57 min** each, **1.675 / 1.708 s/step**,
peak **~9.84 GB** of 24 GB) and both CE gates pass with wide margin in both seeds, but **one of `score.py`'s 15 metrics

`scripts/arm.sh`'s own comparison prints `arm: FAIL` twice. This note is tracked at the user's instruction *with* that

seeds, at the same size, is a **systematic difference**: the shim's arm flags exactly two fewer borderline cards at the
0.9 threshold than the Python arm it is compared against (seed 0: 5 vs 7; seed 1: 6 vs 8; band 1 unit). Everything
else — all three CE gates in both seeds, and 14 of 15 `score.py` metrics — is inside.

## The probe, and the plan's wrong number

A 20-step TF32 probe preceded the arm on the same 20 batches M7.3 timed (same binary, same adapter, only the mode
changed): **1.67 s/step vs exact's 8.94 — 5.34x**; dev check 4 s vs 31 s; 20 steps 53 s vs 278 s. Probe sanity: dev soft
CE 0.77123 (exact 0.77090), loss 1.3240 vs 1.3228 — the TF32-vs-exact spread M7.2 measured.

**M7.4's plan text is wrong and this run corrects it.** It says "at M7.3's 8.94 s/step a full arm is ~9 hours on the
card". 8.94 is the shim's deliberately naive correctness-first fp32 kernel (`libtinycublas/gemm.cu:7`), which exact mode
must use to match Python's true fp32; the arm never runs that kernel — TF32 dispatches to `tinyblas_gemm_f32_tc`
(64×64×32 tiles, shared memory, wmma tensor cores). The measured arm is **1.7 s/step, 1 h 57 min**. Appendix B's
"full-arm s/step not run — at 8.94 s/step it is ~9 h" belongs to the same error and should be replaced by this number.
