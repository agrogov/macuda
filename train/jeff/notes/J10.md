## The interface later tasks call (please do not change the names)

```c
// kernels/rope.h — host table builder + the two launches (device pointers, one stream, cudaStream_t last)
void rope_tables(float *cos, float *sin, int lmax);                       // [lmax][64], fp32, host-side
void rope_fwd(float *x, const int *row_off, const int *row_of, int n, int heads, int head_dim,
              const float *cos, const float *sin, cudaStream_t s);        // in place, first 64 dims of each head
void rope_bwd(float *dx, const int *row_off, const int *row_of, int n, int heads, int head_dim,
              const float *cos, const float *sin, cudaStream_t s);        // in place on the cotangent

// kernels/conv.h
void conv_fwd(const float *qkv, const float *wconv, const int *row_of, const int *row_off, float *pre, float *out,
              int n, int channels, cudaStream_t s);                        // pre = conv, out = silu(pre)
void conv_bwd(const float *dout, const float *pre, const float *wconv, const int *row_of, const int *row_off,
              float *dqkv, int n, int channels, cudaStream_t s);           // dpre = dout*dsilu(pre), transposed conv
```

* `row_off` is the `off[]` prefix-sum array (`[nrows + 1]`, `off[nrows] == n`), `row_of` the per-token row index
  (design §7: "the kernel finds b ... from a precomputed `row_of[N]` int array (simpler; do that)"). Both are device
  pointers in the wrappers; the model uploads them once per step as §7 says.
* `wconv` is the checkpoint's `[6144, 1, 4]` **flattened to [channels][4]** and already fp32 — the loader converts it
  like any other bf16 tensor; `wconv[ch*4 + k]` multiplies `qkv[t-3+k, ch]` (design §3.6).
* The conv weight is frozen (design §2.1: only LoRA A/B and the readout are trainable), so there is **no** `dwconv`.
* RoPE tables are `[lmax][64]` with `lmax` = the longest row (1026), built once by `rope_tables` and uploaded; the
  position of a token is `t - row_off[row_of[t]]`, never the packed index.
* `head_dim` must be >= 64 (the model's head is 256); the wrappers and the reference are a no-op below that. The
  rotation is the first `JT_ROPE_DIM = 64` dims, so `partial_rotary_factor` 0.25 of `head_dim` 256 — dims 64..255 pass
  through.

### The ragged row-boundary test the plan names

`k_conv`'s `case_row_boundary()` uses rows `{5,7,6}`, 17 channels: row 1 is tokens [5,12), so its last 3 tokens are 9,10,11
and row 2 is [12,18) with first tokens 12,13,14.

* forward: randomise row 1's last 3 tokens (values in [-6,6] versus the original [-1,1]); row 2's first 3 tokens must be
  **bit-identical** (`err=0`, gate 1e-9) in `pre` and in `out`, and row 1's own last 3 must change (`max diff > 1e-2`,
  ok) so the check is not vacuous;
* backward, the other bound: randomise `dout` at row 1's last 3 tokens; row 2's first 3 `dqkv` are bit-identical
  (`err=0`) and row 1's own change; plus `dqkv` at row 2's first token is non-zero (a backward that zeroed row starts
  "to be safe" would pass the boundary check and fail this one).

`k_rope`'s row-start check is the same idea for positions: at every row's first token `p = 0`, so the rotation must be
the identity (`err=0` at gate 1e-9). A packed index used as a position would rotate the first token of every row after
the first and fail it.

## Notes for the next tasks

* `conv_bwd` recomputes `dpre = dout * dsilu(pre)` per tap (4 taps, no scratch buffer, no atomics) instead of
  materialising a `dpre` array, so its signature has no workspace argument. If M8 ever wants the scratch version, the
  arithmetic and the reference stay the same.
* Launch shapes: RoPE is `grid(n)` blocks of 256 (one block per token, threads stride `heads * 32` pairs — a 64-row
  batch is 65664 tokens, which overflows `gridDim.y`, so tokens go on x); the conv is `grid(n)` blocks of 256, threads
  striding the channels (24 iterations at 6144). Both have no shared memory and no cross-thread reduction.
* Positions and taps come only from `row_off`/`row_of`; nothing in these kernels knows about `off[0] == 0`, so a
  sub-slice of a packed batch would work if a caller ever passes a shifted `row_of` (it does not).
* `rope_tables` is a plain host function in `kernels/rope.cu` (compiled by nvcc's host compiler on gpubox, by clang
  through tinycc on the Mac), not a kernel: the model builds the tables once and uploads them (design §3.3, and §12's
  "no `cudaMemcpyToSymbol`").
