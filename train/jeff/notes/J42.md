# J42 — the structural check accepts prep.py's batch order (unblocks plan M6.3 / M6.4)

`src/main.c`'s `split_check_structure` decided which row count batch `k` of an epoch holds with `expected_rows(n_rows,
batch, k % per_epoch)`: full batches first, the one short batch last. But `py/prep.py` writes CLM-8B's
`train.py:batches()` order — length-bucketed, cut, then `rng.shuffle(out)` — so the short batch lands anywhere (design
§2.3). On the full split (28,645 rows, `--batch 8`, 3,581 batches) the 5-row batch is at index 2,845, so jefftrain
rejected its own correct prep and exited 1 before step 1: exactly what aborted G-m63 (plan M6.3) and G-m64 (plan M6.4).

One file changed, `src/main.c` — nothing else (`git status --short` is ` M train/jeff/src/main.c` plus this note). No
`.jtb` format change, no `py/prep.py` change, no Makefile, no `cuda-shim/`, `vendor/` or CLM-8B change, no kernel, no
gate, no tolerance, no compute mode.

## What changed

* `expected_rows()` is gone (`-Wunused-function` otherwise; nothing else called it).
* New `sidecar_rows_per_batch()`: reads `<split>.prep.json`'s `rows_per_batch` — the list `py/prep.py:193` already
  writes, one row count per batch, every epoch's list in file order — into a malloc'd array. `NULL` when the sidecar is
  absent (the synthetic fixtures) or has no such integer list. `Split` and `s->sidecar` (parsed by `split_check_sidecar`
  already) are what it reads, so no new file is opened and `src/json.c`'s scanners are untouched.
* `split_check_structure()` now: (a) keeps the `n_batches == ceil_div(n_rows, batch) * epochs` count check verbatim,
  with its message reworded to end in "the file was written with a different --batch/--epochs"; (b) with a sidecar,
  rejects a sidecar whose list length is not `n_batches` and then compares each batch's row count with
  `rows_per_batch[k]` (and requires each entry to be 1..`--batch`); (c) without a sidecar, requires each batch to hold
  1..`--batch` rows; (d) in both cases keeps the `JT_MAX_ROWS` bound, the `rows[i] < n_rows` check, and adds the
  epoch-sizes-sum-to-`n_rows` check the batch list has to satisfy anyway (so a real different `--batch` still fails).
  `per_epoch` and the training loop are unchanged.
