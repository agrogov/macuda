## The change (one file, `src/layer_attn.c`)

### `layer_attn_mixer_bwd`, design §4.7 in reverse of the forward

| step | call |
|---|---|
| `d_o_gated = dres` through `o_proj` | `linear_bwd(o_proj, x = o_gated, u = u_o, dy = dres, dx)` — `dres` is read and not written again until the last line, so it *is* the `dy`; `dx` gets its own buffer (linear_bwd refuses `dx == dy`) |
| `d_o, dgate` | `k_sigmoid_gate_bwd(d_o_gated, o_pre, gate, ...)`; `gate` is re-split out of the saved `qg` with `jt_qgate_split` |
| `o_gated` | recomputed with `k_sigmoid_gate_fwd(o_pre, gate, ...)`: it is both `o_proj`'s `x` and the gate backward's `o` (2048 floats/token not saved) |
| per row (design §8.2's second block) | `dP = dO V^T` (ta 0, tb 1), `dV = P^T dO` (ta 1), `attn_softmax_bwd(P, dP)` (the 1/16 is inside), `dQ = dS K` (ta 0, tb 0), `dK = dS^T Q` (ta 1), then `from_head_major` + `kv_reduce` for dk/dv |
| P | recomputed from the saved q and k by the forward's own two calls (score GEMM + `attn_softmax_fwd`), so the softmax backward differentiates the forward's P bit for bit, not an approximation |
| `dq, dk` | `rope_bwd` (one launch each over the packed batch: the positions are row-local) |
| `q_norm/k_norm` backward | `rmsnorm_bwd(d = 256, zero-centred)`, rows `n*8` and `n*2` |
| `dqg` | `jt_qgate_merge(dq_pre, dgate, dqg)` — the adjoint of `qgate_split` |
| `da` | `linear_bwd(q_proj)` (writes) then `k_proj`, `v_proj` (`accumulate_dx = 1`): all three have the same input `a`, design §4.6 |
| `dres` | `rmsnorm_bwd(x_in, input_norm, da, r_in, ...)` then `jt_add_inplace` — the residual adds, never overwrites |

Four things worth writing down:

* **The save layout is now one function each way.** `attn_saves()` used to take fifteen buffers one at a time; it is
  now `attn_saves_floats(n)` (12,875 per token) and `attn_save_ptrs(n, base, &s)`, and the forward takes **one** block
  of that size (`jt_save_alloc` in SAVE mode, `jt_work_alloc` otherwise). Because the arena is a bump allocator,
  fifteen allocations of `s1..s15` land exactly where one of their sum did — the whole-model forward dump below is
  byte-identical before and after this change. The two orders now cannot drift apart, which is the point.
* **Where the backward finds the block: the arena's base.** `layer_fwd(SAVE)` resets the save half and runs the mixer
  first (src/model.c:439-445), so the attention's saves start at `arena[0]`; a caller that invokes the piece directly
  resets it itself (src/layer.h) — the convention `head_bwd` already uses. The check is
  `c->save_at >= attn_saves_floats(n)`, so a bwd without a SAVE pass behind it fails with a message instead of reading
  whatever is there (that case is exercised, see 4).
* **`dqg` is reused, not added.** The backward needs the split's *gate* half but not its q half (`q_pre` is saved), so
  `jt_qgate_split` writes its throwaway q into `dqg` — the buffer `jt_qgate_merge` fills at the end. One pass over
  `[n,4096]` instead of another 2048 floats/token of saves.
* **Argument checks return `JT_LAYER_FAIL` with a message**, like the forward: null context/model/LoRA/x/b/dres, `n !=
  b->n`, a row table that is not a prefix sum or a row longer than `c->lmax`, and saves bigger than the save half. An
  empty batch is `JT_LAYER_OK`. Nothing here synchronises the stream.

### One row's backward, `attn_row_bwd`

Design §8.2's second block as six `gemm_batched` calls on the same head-major buffers the forward used
(`[8][L][256]`), plus `[8][L][L]` for P, dP and dS. **dP takes over the score buffer's words** once P exists (the
scores are dead after `attn_softmax_fwd`), so a row costs 3 L x L slabs and not 4; the row's other buffers are
`qh, kh, vh` (re-derived), `doh, dqh, dkh, dvh` and one token-major `[L,2048]` scratch. 16,384 x lmax + 24 x lmax^2
floats, taken from the work half once per call and given back (design §6.2).

### 3. The driver, and the trap I fell into first (worth recording for M5.1 item 4)

`test/test_layer.c` is J23's and knows only forward modes; as in notes/J26.md, the backward driver is a **throwaway
added to the gpubox tree only** (`test/test_attn_bwd.c`, 415 lines, deleted again before the final build — the
worktree never sees it; the Makefile's `test/test_*.c` wildcard builds it with no Makefile edit). It:

1. loads the checkpoint + adapter + ref, sizes the context from the reference's `in.off`/`in.ids` (the `--dump-forward`
   batch: rows [0,1] of 37 and 70 tokens, 5 options),
2. `jt_saves_reset` + `layer_attn_mixer_fwd(..., JT_FWD_SAVE)` and compares `layer.{i}.post_mixer` at design §10.2's
   1e-3 (so the activations the gradients are taken at are the model's own),
3. `lora_zero_grad`, `dres = grad.layer.{i}.out`, **then the hand-rolled MLP backward of the same layer accumulated into
   `dres`** (the code of test/test_linear.c's `run_mlp` plus the last `rmsnorm_bwd`, so `layer_mlp_bwd` — another
   task's — is not on this gate's dependency path), then `layer_attn_mixer_bwd(x_in, dres)`,
4. compares the 8 attention LoRA keys and then `dres` against `grad.layer.{i-1}.out`,
5. runs the directional finite difference (below), and the contract/accumulation checks of 4.

**The trap, which cost the first run and is the thing M5.1 item 4 must keep:** the mixer's `dy` is `dL/d(post_mixer)`,
not `grad.layer.{i}.out`. The layer is `post_mixer = x + mixer(...)`, `out = post_mixer + mlp(...)`, so
`dL/d(mixer out) = grad.layer.{i}.out + the MLP's path` — i.e. **`layer_bwd` must run the MLP first and hand the
accumulated `dres` to the mixer**, which is exactly what src/model.c:459-461 does ("the MLP is the last thing the
forward did"). Feeding the mixer `grad.layer.{i}.out` instead gave *every* LoRA key at 0.36-0.72 relative and
`grad.layer.2.out` at 0.15 — an O(1) error with no subtlety in it, and a first version of this test that did the MLP
path second and compared only the *mixer's own* delta would have hidden it.

The finite difference is design §10.2's honest fallback for the one quantity the reference has no key for. With
`F(x) = x + mixer(norm(x))` and `dy = dL/d(post_mixer)`, `d/dt <dy, F(x + t v)> = <dy + mixer path, v> = <dres, v>`,
so two extra `JT_FWD_ONLY` passes per direction test all 1024 input columns at once. Two calibration facts:

* **`h` has to be small, because `|x_in|` is small.** `rms|x_in|` is 0.062 at layer 3 and 0.35 at layer 23, so `h =
  1e-2` is a 16% perturbation and the *truncation* error dominates: layer 3's worst direction disagrees by 3.6e-1 at
  `h = 1e-2`, 3.3e-2 at 3e-3, 5.5e-4 at 3e-4 and 1.4e-4 at 2e-4 (the default). Below ~1e-4 the forward's own
  fp32 rounding takes over again (h = 1e-4 gives 1.1e-3 on the worst direction). `h = 2e-4` is the minimum of the
  two error curves at this scale.
* **The metric is design §10.2's over the direction vector** (`max|analytic - fd| / max|analytic|`), not a per-direction
  relative error: a direction whose analytic value happens to be small divides a fixed ~1e-4 of forward rounding by
  nothing, so a correct gradient prints 5.5e-3 (layer 15's direction 0 at `h = 2e-4`: analytic 5.4e-2, |diff| 3.0e-4)
  or 1.8e-3 (layer 7's direction 4). Per direction the number is printed, not gated.

* **Cost.** Per row the backward is 6 batched GEMMs — `dP` and `dS K`/`dS^T Q`/`P^T dO` at `8 x L x L x 256`, i.e. 3x
  the forward's 2 — so at `L = 1024` a row's attention goes from 8.6 to 25.8 GFLOP; plus five `linear_bwd`s (four
  projections and the norm, ~2x the forward's dense math, J25's note) and a handful of elementwise passes. The
  projection sides dominate at the plan's batch, so the attention mixer's backward is a little over 2x its forward, as design §15
  assumes for the whole step.
* **For M5.2 (`--dump-backward`).** After `layer_attn_mixer_bwd` the four projections' `dA`/`dB` are in
  `ctx->lora->grad` and `dres` holds `dL/d(layer i's input)` — but the reference's key for that is
  `grad.layer.{i-1}.out`, which the layer loop can only compare *after* the MLP's path of layer i is added, so the dump
  has to write `grad.layer.{i}.out` from the **entry** value (`head_bwd`'s / the previous layer's `dres`) and pass the
  accumulated one along. `layer_bwd` already orders this correctly; the dump must not re-derive it.
* **For M5.4 (the card checkpoint).** The line to run is `test_attn_bwd --layer 3` (and e.g. `--layer 7`) with
  `JT_EXACT=1 TINYCUBLAS_TC=0`; the numbers above are the gates it should print. It needs no card-only code path, and
  the six batched `gemm_batched` calls it adds are the first users of `(ta, tb) = (1,0)` on `L x 256 x L` shapes with
  `batch = 8` — `test_gemm` covers the four flag combinations but no layer-level user covered `ta=1` at this shape
  before the backward (J25 covered `ta=1` for `dy^T u` and `e^T x`).
* **For M5.1 item 4 (the layer loop).** `layer_attn_mixer_bwd` needs `x_in` = the layer's input (not `post_mixer`,
  which is the MLP's) and reads the saves of the `layer_fwd(SAVE)` that immediately preceded it; `layer_bwd` resets
  nothing, so the loop's `jt_saves_reset` before each `layer_fwd(SAVE)` is what keeps them apart.
