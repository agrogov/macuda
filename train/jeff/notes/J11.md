## What was written

`ref/attn.c` — `ref_attn_softmax_fwd(S, P, L, heads, scale)` and `ref_attn_softmax_bwd(P, dP, dS, L, heads, scale)` in
`[heads][L][L]` row-major layout, s fastest. Forward: `P = exp(scale*S - max) / sum` over `s <= t`, exactly 0 above the
diagonal. Backward: `dS = scale * P * (dP - sum_{s<=t} P*dP)`, exactly 0 above the diagonal. Sums are accumulated in
double even in the float build (the reference is the oracle; `ref/real.h`'s rule of one rounding).

`ref/head.c` — `ref_ce_head(logits, n_opts, targets, wrow, wgroup, B, loss_out, dlogits, probs_out)`: log-sum-exp softmax
per row, `ce = -sum_j t_j * log p_j`, `loss_out[r] = (wrow[r]/wgroup) * ce`, `dlogits[r][j] = (wrow[r]/wgroup) *
(p_j * sum_k t_k - t_j)`, `probs_out = p`. Plus design §4.1's two readout lines as `ref_head_readout_fwd` (logits = z R^T,
dead options masked to -1e9) and `ref_head_readout_bwd` (`dz = R^T dlogits`, `dR += dlogits^T z`) — the oracle for M5's
cuBLAS pair; they have no kernel of their own on purpose (they are GEMMs).

`kernels/attn.cu` — one 256-thread block per (head, t) row (`grid = heads*L`, capped at 65535 with a grid-stride loop),
two passes over the live prefix (max, then sum), fixed fp32 tree reductions in shared memory, then the normalised write
including the exact zeros. The backward does the dot product the same way and writes `scale * P * (dP - dot)`. No
atomicAdd anywhere, so the result is bit-stable run to run (design §8.1). `-FLT_MAX` is a macro, not a `__constant__`.

`kernels/head.cu` — one block per row: max, `lse = max + log(sum)`, then `sum(t)` and the loss, then p and dlogits. 255
options fit one thread each; the loops stride so any width works. `dlogits` and `probs_out` may be NULL (loss-only /
evaluation path), which the test exercises.

## Semantics M5 must match (also in the headers)

* **Logits arrive already masked.** `ce_head` does only the softmax part (plan M2.5, design §4.1 "dead ones are -1e9"):
  the caller puts `-1e9f` in every dead option and `0` in its target — exactly train.py's
  `logits.masked_fill(~live, -1e9)` and its zero-padded `target` tensor, sliced to the batch's widest row
  (`[:, :live.shape[1]]`). `n_opts` is that width, one value for the whole batch.
* **The loss is the weighted one.** `loss_out[r] = (wrow[r]/wgroup) * ce_r`, so `sum_r loss_out[r] ==
  (per * wt).sum() / gw` (train.py's batch loss) and `dlogits` is the exact gradient of that sum. `wgroup` is `gw`, the
  sum of the row weights over the accumulation group. With weights none and accum 1 it is the batch size.
* **`sum(t)` is carried.** `dlogits` uses `p_j * sum_k t_k - t_j`, the design's formula, not `p_j - t_j`: train.py only
  guarantees `|sum(t) - 1| <= 1e-4`. The `n255u`/`n2` cases check unnormalised targets for exactly this.
* **Dead options are exactly 0** in `probs_out` and in `dlogits` (exp underflows), and the loss is finite because
  log-sum-exp keeps a dead option's `log p` at the finite `-1e9 - lse`; `t_j = 0` then multiplies to 0, where a literal
  `-inf` would give NaN (which is what torch does too).
* **Attention carries the scale inside.** Pass the raw GEMM score; `scale = 1/16` reaches the softmax and comes back
  multiplied into `dS` (design §8.2). `P` is a plain `[heads][L][L]` plane, one launch per packed row, so the caller
  slices `off[b]..off[b+1]` itself; the kernel knows nothing about row boundaries.
* Signatures keep the plan's argument order and append `cudaStream_t s` last, like `misc.h`'s `jt_fill`.
