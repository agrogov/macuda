## The interface later tasks use (M4/M5's forward and backward)

Both headers are named `norm.h` on purpose: a `.cu` includes the one beside it, a reference test includes its own
(`"../ref/norm.h"`). The reference works in `real` (ref/real.h: float, or double under `-DJT_REAL_DOUBLE`); the kernel
wrapper is float-only and takes a `cudaStream_t` last. `eps` is the model's `rms_norm_eps`, 1e-6 everywhere
(design §3.1), so it is a constant (`JT_NORM_EPS` in ref/norm.h, `JT_NORM_EPS_F` in kernels/norm.h), not an argument.

```c
/* ref/norm.h */                                     /* kernels/norm.h */
ref_rmsnorm_fwd(x, w, y, r, rows, d, zero_centred);   rmsnorm_fwd(x, w, y, r, rows, d, zero_centred, s);
ref_rmsnorm_bwd(x, w, dy, r, dx, rows, d, zc);        rmsnorm_bwd(x, w, dy, r, dx, rows, d, zc, s);
ref_gated_rmsnorm_fwd(x, w, z, y, r, rows, d, zc);    gated_rmsnorm_fwd(x, w, z, y, r, rows, d, zc, s);
ref_gated_rmsnorm_bwd(x, w, z, dy, r, dx, dz,         gated_rmsnorm_bwd(x, w, z, dy, r, dx, dz,
                     rows, d, zc);                                      rows, d, zc, s);
ref_l2norm_fwd(x, post_scale, y, r, rows, d);         l2norm_fwd(x, post_scale, y, r, rows, d, s);
ref_l2norm_bwd(x, dy, r, post_scale, dx, rows, d);    l2norm_bwd(x, dy, r, post_scale, dx, rows, d, s);
```

* Rows are `[rows][d]`, row-major. A row is one token for `rmsnorm_*` (d = 1024 final norm, d = 256 q_norm/k_norm) and
  one (token, head) pair for `gated_rmsnorm_*` / `l2norm_*` (d = 128, rows = tokens * 16), as design §8.1 says.
* `r` is one `real`/`float` per row, written by the forward and **required** by the backward (design §4.3 "save r per
  row"): the backward does not recompute it. (Plan M2.2's "two reductions" for `rmsnorm_bwd` describes a variant that
  recomputes r; the design says to save it, so this kernel does one row reduction — `mean(gy * x)` — and takes `r` in.)
* `zero_centred` is the (1 + w) vs w pitfall: 1 for every `Qwen3_5RMSNorm` (w init zeros, l.841), 0 for the GDN gated
  norm (w init ones, l.218) and for the GDN weight generally. Both values are gradchecked and both are tested on the
  device, for `rmsnorm_*` and for `gated_rmsnorm_*` (which takes the same flag for the same reason).
* `post_scale` is the model's 1/sqrt(128) on q and 1 on k (design §3.6), inside both l2norm directions so no second
  pass over the output is needed.
* Gradients that are not produced, deliberately: no `dw` anywhere (every norm weight is frozen, design §2.1);
  `gated_rmsnorm_bwd` writes both `dx` and `dz` (`dz` is 4.8's `dz` into `in_proj_z`).

Launch shapes (design §8.1, plan M2.2), chosen by the wrapper from `d`, never by the caller: `d > 256` → one 256-thread
block per row (4 elements per thread at d = 1024); `d <= 256` → one warp per row (4 elements per thread at d = 128, 8 at
d = 256); `gated_rmsnorm_*` and `l2norm_*` always use one warp per row, eight warps (256 threads) per block, so the grid
is `ceil(rows/8)` and rows need not be a multiple of eight. Reductions are `__shfl_xor_sync(0xffffffff, v, o)` with
o = 16,8,4,2,1 and then shared memory across the warps for the 256-thread form — no `atomicAdd`, no
`__constant__`, so a launch is bit-for-bit repeatable.

## Extra: the reference is the model's norm, not just self-consistent

A finite-difference gradcheck proves a backward matches its own forward; it cannot prove the forward is the right
function. So the reference forward was compared once against the real modules in CLM-8B's venv (throwaway programs in
/tmp, nothing added to the repo, synthetic random inputs only):

```
$ /Users/arogov/Downloads/CLM-8B/.venv/bin/python /tmp/j08/xc.py     # ref/norm.c (float) vs transformers 5.17.0
rms     rows=  4 d=1024  y rel=1.535e-07  r rel=1.737e-07   # Qwen3_5RMSNorm, weight copied, (1 + w)
rms0    rows=  4 d=1024  y rel=2.154e-07  r rel=1.737e-07   # same formula with w instead of (1 + w)
gated   rows=  5 d= 128  y rel=1.260e-07  r rel=1.187e-07   # Qwen3_5RMSNormGated (silu gate, weight ones-init)
l2      rows=  5 d= 128  y rel=7.173e-08  r rel=8.393e-08   # l2norm * 1/sqrt(128)
l2k     rows=  5 d= 128  y rel=5.072e-08  r rel=8.393e-08   # l2norm, no extra scale
$ python /tmp/j08/xb.py             # ref/norm.c (-DJT_REAL_DOUBLE) backward vs torch autograd, float64
rms     rows=3 d=1024  dx rel=4.081e-16
rms0    rows=3 d=1024  dx rel=4.019e-16
gated   rows=4 d= 128  dx rel=3.029e-16  dz rel=4.547e-16
l2      rows=4 d= 128  dx rel=5.182e-16
l2k     rows=4 d= 128  dx rel=2.748e-16
```

So the forward matches transformers' own `Qwen3_5RMSNorm` / `Qwen3_5RMSNormGated` / `l2norm` to fp32 rounding, and the
three backwards match `torch.autograd` on those formulas to machine precision. That closes the one hole the gradcheck
leaves open (a forward and backward that are wrong the same way).

## Notes

* The tinycc shim build compiles the host half of `kernels/norm.cu` with clang, so `static inline` host helpers and
  `__device__ __forceinline__` device helpers are fine (nothing here depends on that beyond what misc.cu does).
* `kernels/norm.cu` includes `src/util.h` only for `JT_SYNC_DEBUG` (a no-op unless `-DJT_DEBUG=1`); it pulls in the
  cuBLAS header, which is why `check-symbols` now counts 15 cuda*/cublas* symbols instead of 10 — all 15 come from the
  existing `src/gemm.c` + `util.h` declarations and all are defined by the shim.
* `test/grad_norm.c` uses `../../ref/norm.h` via `"../ref/norm.h"` from `test/`, and `test/k_norm.c` includes both
  headers (they have the same basename but nothing clashes: `real` refs vs float kernel wrappers).
