# J48 — M8.3 Re-profile attention after the transpose fix

J38's ceiling for a flash-style attention (10.1% TF32 / 17.1% exact) was measured before J44 fixed the head-major
transposes. Re-measured at the same shape (batch 8 x accum 1, 20 steps, median over steps 3..20, 3 runs per
configuration), the attention core is now **2.71% of a TF32 step and 5.24% of an exact one with the transposes left
out**. That is below the card's 4% TF32 threshold, so flash is **not** worth building: the remaining transposes are
worth more than the scores/softmax/PV/backward block they would replace.

## 1. What was run

Prerequisite first (standing rule 7):

```
$ sh train/jeff/scripts/prereq-check.sh J43 J44 J45
prereq: J43 J44 J45 PASS
```

`notes/J38.wip.patch` no longer applies to `src/layer_attn.c` because J45 (`JT_ATTN_BATCH`) moved the per-row calls
into `attn_chunk_prep()` / `attn_row()` / `attn_chunk_tail()` and their backward twins. I ported the timing switches by
hand into those functions (the temporary diff is `notes/J48.wip.patch`; it is measurement scaffolding, not a
proposal), built it on gpubox, then reverted `train/jeff/src` with `git checkout -- train/jeff/src`. No tree change
survives.

gpubox was used with `export JT_REMOTE=macuda-train/wt-J48`:

```
$ JT_REMOTE=macuda-train/wt-J48 sh train/jeff/scripts/gpubox-build.sh
... nvcc/gcc build of build/nv/jefftrain, exit 0 ...
```

A first cross-check used J43's A/B script (A = HEAD `14204b9`, B = the ported tree), TF32, 3 interleaved pairs. Its

are quoted.

## 3. The ceiling

The clean measure is J38's ablation, not the event-synced `JT_PROF` phases (those add a sync per phase and inflate the
step itself: 0.41722 vs 0.38764 TF32, 0.50689 vs 0.47593 exact). `JT_NOATTN` removes the whole per-row block
(prep + scores + softmax + PV + from_head_major and the backward), and `JT_NOTR` removes only the transposes/layout
passes. Their difference is the attention core with the transposes left out:

| | TF32 | exact |
|---|---:|---:|
| whole per-row block (`JT_NOATTN` Δ) | 4.74% | 5.59% |
| transposes only (`JT_NOTR` Δ) | 2.04% | 0.35% |
| **core = NOATTN − NOTR** | **2.71%** | **5.24%** |

So the ceiling is **2.71% TF32 / 5.24% exact**. TF32 is below the card's 4% line → `DECISION: NOT LANDED`. For
completeness, a hypothetical kernel that also subsumes the remaining 2.04% TF32 transpose cost would have a whole-loop
upper bound of 4.74%, but the card defines the ceiling with the transposes left out, and the design itself
(`D§4.7`) says no flash attention is needed at this L.

`JT_NOSM`/`JT_NOSMZ` are secondary evidence: the forward+backward softmax alone is 0.27–1.23% TF32 and 0–4.33% exact
(the two exact probes disagree because `JT_NOSM` leaves stale P and `JT_NOSMZ` zeroes P; as in J38, neither is a clean
kernel-time measurement). The scores/PV GEMMs plus the backward are the rest of the core.

## 4. What this means for J49/J50

Do not cut a flash-attention card on the strength of the attention core: after J44 its measured ceiling is 2.71% of a
TF32 step, below the 4% threshold, and the transposes that J38 saw as the real prize are already fixed (now only
2.04% TF32 / 0.35% exact). `TOGGLE: none`; nothing landed, and the only files left are this note and the temporary
instrumentation patch.

## 5. Honest limits

* Per-step timings are wall-clock differences between flushed log lines, not CUDA events; the ~0.1 ms resolution is
  ample for the 4% decision but the `JT_PROF` event numbers are not used for it.
* 3 runs per configuration, as the card asks. Exact `JT_NOTR` has the widest spread (0.01867 s); taking the
  NOATTN-only delta gives 5.59% and subtracting the NOTR median delta gives 5.24%, so the exact side is resolved only
  to "about 5.2-5.6%" by this run set. It stays above 4% under that reading while TF32 is 2.71% and well below it.
* No card run (`TINYNV_HW` nor `nv_shim_step.sh`); everything above is gpubox under `~/macuda-train/.gpu.lock`.
* No Makefile, script, test, ref, kernel, shim, vendor or CLM-8B change was kept; no tolerance, gate or compute mode
  was touched; `src/layer_attn.c` is back to HEAD and `git status` shows only `notes/J48.md` and
  `notes/J48.wip.patch`.
