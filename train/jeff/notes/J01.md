## Notes for the tasks that build on this

* `make nv` is the default goal (`ARCH` defaults to `sm_120`); `make shim` **requires** `ARCH=` and prints the plan's
  message otherwise. `shim-build` / `nv-build` are the internal halves (no guards) — call `shim` / `nv`.
* Object names in the flat build dir: kernel `misc.o`, host `host_misc.o`, refs `ref_x.o` / `refd_x.o` (double),
  tests `test_x.o`, extra TUs `k_x.o` / `grad_x.o`. That is why `src/head.c` and `kernels/head.cu` can coexist and
  `nm -u build/shim/*.o` (check-symbols) still sees every object.
* Host builds get `-D_GNU_SOURCE` (glibc hides `clock_gettime`/`mmap` under `-std=c11`); the shim build also gets
  `-DJT_SHIM`, the CPU build `-DJT_CPU` (and `util.h` then declares no CUDA anything). `test/test_hello.c` skips its
  value check under `JT_SHIM` unless both `TINYNV_HW` and `TINYNV_SOCKET` are set.
* `test-cpu` links a CPU test only with the float ref objects plus `src/<same name>.c` when it exists
  (`test_st` → `src/st.c`, `test_jtb` → `src/jtb.c`); `gradcheck` is the only binary built with the double refs.
  A new CPU test that needs another host file has to be named after it.
* A test binary run with no arguments must exit 0 on the null device (README.md); `test-null` relies on it, and
  `scripts/card-check.sh`'s `DRY=1` will too.
* Nothing in `cuda-shim/`, `vendor/` or CLM-8B's vendor tree was touched; no card run was made (M0 has none — J01 ran
  only the null device and gpubox).
