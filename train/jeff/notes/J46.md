# J46 — M8.1a: f32 → bf16 cast kernel with CPU reference

Plan M8 item 1's missing first piece (J36 named it and could not build it). This adds one function and its reference and
its tests; nothing calls it yet, so no code path changed, no toggle and no timing (`ab.sh` / the parity gates do not
apply to an unused function — rule 8 is about behaviour, and there is none to measure).

**What landed**

| file | what |
|---|---|
| `ref/misc.h`, `ref/misc.c` | `void ref_f32_to_bf16(const float *src, unsigned short *dst, size_t n);` — the reference, written first (plan rule 2), as explicit sign/exponent/mantissa fields and a compare-to-half, not as the bit trick the kernel uses, so the two are two descriptions of one rule |
| `kernels/misc.h`, `kernels/misc.cu` | `void jt_f32_to_bf16_n(const float *src, unsigned short *dst, size_t n, cudaStream_t s);` — grid-stride over 256-thread blocks (`jt_grid_stride`, the same launch shape as `jt_bf16_to_f32_n`), no-op at `n == 0` |
| `test/k_misc.c` | 13 new checks in the `misc` group (83 → **96**), bit-for-bit against the reference |

Rounding is round-to-nearest-even, done on the integer bits (`u += 0x7fff + bit16`, the standard ties-to-even add), so
±0, the denormals, ±inf and the exponent carry at both ends of the range (0x7f7f+1 = +inf; a bf16 subnormal's 0x007f+1 =
the smallest normal) are all the same code path. A NaN is tested first and becomes sign | quiet bit | the 7 payload bits
a bf16 has room for — **exactly the rule `test/harness.h`'s `jt_f32_to_bf16` already states**, so a fixture built with
that helper and this kernel agree on every pattern.

**Why not `__float2bfloat16`** — measured, not assumed (probe on gpubox, `-arch=sm_120`, CUDA 13.2, `/tmp` only):

```
00000000  cvt=0x0000  rn=0x0000        3f808000  cvt=0x3f80  rn=0x3f80   (tie -> 1.0, correct)
7fc00000  cvt=0x7fff  rn=0x7fff        3f818000  cvt=0x3f82  rn=0x3f82   (tie -> up, correct)
ffc00000  cvt=0x7fff  rn=0x7fff        0000ffff  cvt=0x0001  rn=0x0001   (denormal, correct)
7f800001  cvt=0x7fff  rn=0x7fff        00000001  cvt=0x0000  rn=0x0000   (denormal, correct)
7fffffffu cvt=0x7fff  rn=0x7fff        7f7fffff  cvt=0x7f80  rn=0x7f80   (overflow -> inf, correct)
```

The hardware's `cvt.rn.bf16.f32` is right on every *value* but returns **0x7fff for every NaN** on sm_120 (no sign, no
payload), which is a card/driver detail a bit-exact test cannot be pinned to. The integer version gives the same answer
on every architecture, which is what a bit-equal gate needs (and costs a few integer ops on a bandwidth-bound copy).

**Cross-check of the reference** (host-only, throwaway program in `/tmp` linking `ref/misc.c` and the two helpers copied
out of `test/harness.h`): 8,192,000 random fp32 bit patterns (NaN, inf, denormals, ties, random signs), **0 differ**
between `ref_f32_to_bf16` and `jt_f32_to_bf16`. The first version of this change *did* disagree — the reference
canonicalised NaN to 0x7fc0 while the kernel kept the payload bits — and the new check said so:

```
$ ./build/nv/test_kernels misc | grep -A1 'first mismatch'
  first mismatch at 56: got 0x7fda want 0x7fc0
FAIL f32_to_bf16 random bits n=2516 err=9 tol=0.5
  first mismatch at 24: got 0x7fff want 0x7fc0
FAIL f32_to_bf16 specials n=25 err=1 tol=0.5
```

so the gate measures rather than floors: 9 of 2516 uniformly random bit patterns were NaNs, and one wrong NaN rule is
enough to fail it. (That is also how the harness's helper was found to be the tree's stated rule, and the reference was
moved onto it rather than the kernel.)

**The checks** (`test/k_misc.c`), all bit-equal against `ref_f32_to_bf16`, none of them a tolerance:

* `specials n=27` — ±0, the smallest fp32 denormal (and its negative, which must give −0), the bf16 subnormal boundary
  (0x0000ffff / 0x00010000 / 0x00018000 tie / 0x0001ffff), the ties around 1.0 (0x3f807fff / 0x3f808000 /
  0x3f818000 / 0xbf808000 / 0x3f80ffff / 0x3f810000) and the tie below it that carries into the exponent (0x3f7f8000 /
  0x3f7fffff), FLT_MAX → +inf, ±inf, the bf16-denormal boundary of a normal fp32 (0x00400000), and four NaNs (quiet, with
  the sign bit, signaling, all-payload). Every expected pattern in that list was confirmed by hand against the reference.
* `specials n=1` and `specials last-only n=1` — the shortest launch the wrapper can make, and the last element alone.
* `n=0 is a no-op` — a prefilled destination is unchanged.
* `random n=168` / `random n=2516` — `rnd_fill` over [−3, 3], a weight's magnitude.
* `random bits n=168` / `random bits n=2516` — uniform over the whole fp32 bit space, so every exponent, the denormals
  and the NaNs appear at their real rates (2/256 of the inputs have an all-ones exponent).
* `halfway n=168` / `halfway n=2516` — `(b << 16) | 0x8000` for a random bf16 pattern `b` (all-ones exponents skipped):
  **exactly halfway between two bf16s**, which is the only input where "ties to even" is observable at all.
* `f32_to_bf16→bf16_to_f32 identity n=1/168/2516` — the round trip through the existing `jt_bf16_to_f32_n`; every input
  that a bf16 can hold comes back with its own 32 bits. The 12 bf16 end-cases (±0, the subnormals 0x0001/0x007f, the
  smallest normal, ±1, ±max finite, ±inf) are planted, then random bf16 patterns. NaN is excluded on purpose: quieting a
  NaN is not a bit identity, and its rule is the `specials` case above.

Both ragged lengths (168, 2516) are not multiples of the kernel's 256 threads, so the tail of the grid-stride loop is
covered on both sides of a block boundary; `n=1` covers the degenerate one.

## What J47 gets

`void jt_f32_to_bf16_n(const float *src, unsigned short *dst, size_t n, cudaStream_t s);` in `kernels/misc.h`, exact and
bit-reproducible on every architecture, so a bf16 operand built with it can be compared against
`ref_f32_to_bf16`. It says nothing about design §6.1's alignment rules (extents/leading dims multiples of 8, 16-byte
aligned bases) — those are the GEMM's qualification check, not the cast's, and J36's note already has the measured
numbers for the shapes that qualify (bf16 A/B + fp32 C: 1.8x on both `y = x W^T` and `dx = dy W`).
