# J44 — M8 fix the slow head-major transposes

`jt_to_head_major` / `jt_from_head_major` used to launch `jt_grid_rows(heads)`: 8 blocks for the whole tensor on the
model's 8 query heads, each block walking the complete `rows x 256` slice alone. They now launch one block per
(head, token tile), with the tiles on the x axis and the heads on the y axis; `jt_kv_expand` (the other pure copy named
by the card) uses the same shape instead of one block per token. Both transposes remain pure copies: every output
element is copied from exactly the same input element, so the change is bit-identical by construction.

* `kernels/misc.h`: exports `JT_MISC_TILE 16` (the token tile) so the test can exercise both sides of a boundary.
* `kernels/misc.cu`: `jt_grid_tiles()`, tiled `jt_kv_expand`, tiled `jt_to_head_major` / `jt_from_head_major`.
  `jt_kv_reduce` is untouched: it sums, and its order is unchanged.
* `test/k_misc.c`: `t_head_major(rows, heads, seed)` now runs the GPU/ref comparison and the round trip for heads
  `1, 2, 8, 16` x rows `1, 15, 17, 5750`. `5750` is the arm's largest batch shape (`max_tokens_per_batch`, notes/J39);
  the transposes see one row slice at a time, so it is a stress size for this kernel, not a real single row (`max_len`
  is 795). The existing `kv_expand` / `kv_reduce` cases cover rows 1, 168 and 2516.

This is a fix, not a toggle: unset/`=0` has no meaning here, so `TOGGLE: none`.
