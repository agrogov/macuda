## The change (one file, `src/linear.c`)

```c
y = x W^T                      gemm(0,1)  n x out x in   alpha 1, beta 0
u = x A^T   [n, LORA_RANK]     gemm(0,1)  n x rank x in alpha 1, beta 0    (into u_save, or a work temporary)
y += s u B^T                   gemm(0,1)  n x out x rank alpha s = MT_LORA_SCALE = 2.0, beta 1
```

i.e. the first three rows of design §5's table and design §4.2's `y = x W^T + s * (x A^T) B^T`, in that order, which
is also ref/linear.c's order (it accumulates `W·x` and then adds `s * u·B` per output element, in double). A frozen
linear (`lora == 0`, the GDN `in_proj_a` / `in_proj_b`, design §2.1) runs the first GEMM only and writes nothing else.

Four decisions the frozen struct and design §6.2 forced, all written down in the file's header comment:

* **`u` with no save pointer.** `u` has to exist before it is multiplied by `B`, and design §6.2 forbids `cudaMalloc`
  inside a layer call, so when `u_save == NULL` (a `JT_FWD_ONLY` pass) the temporary comes from the arena's *work* half
  (`jt_work_alloc`, `n * LORA_RANK` floats — 67,200 at N = 4200) and is given back with `jt_work_restore` before the
  function returns. Everything is on `ctx->stream`, so the words are safe to reuse the moment the last GEMM has been
  issued.
* **`struct Linear` carries no rank.** Every LoRA pair in this model is rank `LORA_RANK` (design §2.1, `src/lora.h`,
  which the flat buffer's table is built from), so the rank is that constant, not a field.
* **The factors are slices of the one flat buffer** (design §8.1): `ctx->lora->param + a_off` is `A [rank,in]`,
  `+ b_off` is `B [out,rank]`. Both offsets are bounds-checked against `ctx->lora->n_param` on entry, so a wrong offset
  names the linear (`stem`) instead of reading past the buffer.
* **Argument checks return `JT_LAYER_FAIL`, not `exit()`**: null context/linear/x/y, non-positive `in`/`out`, negative
  `n`, `y == x` (src/linear.h: "both are written in full and may not alias"), a LoRA linear without a parameter buffer,
  and the offset check above. `n == 0` is `JT_LAYER_OK` with no work done. Nothing else in the tree returns
  `JT_LAYER_NOT_IMPL`, so a caller still tells "not written" from "failed" by the code alone.

### 1. "a host-checked linear forward with LoRA matches a CPU reference on gpubox in JT_EXACT mode, rel < 1e-5"

The tree has no linear-only test binary (test_layer starts at a whole layer, and `test/gradcheck`'s `lora` group gates
the *backward*), and adding one would mean editing a file this task does not own. So the check is a throwaway program

4200, cap_rows 8, lmax 1024), puts `A` then `B` at `a_off = 0`, `b_off = rank*in` of the flat `param` buffer, and for
each case fills, from a fixed seed, `x ~ N(0,1)`, `W ~ N(0,1)/sqrt(in)`, `A ~ U(-1/sqrt(in), +1/sqrt(in))` and
`B ~ N(0,1)*1e-2` (the distributions py/make_adapter.py uses), runs `linear_fwd` **twice** — once with a `u_save`
buffer, once with `NULL` so the arena temporary is used — and compares both `y`s and the saved `u` with
`ref_linear_fwd`, `rel = max|got-want| / max|want|`.

numbers, so the arena temporary does the same arithmetic as the caller-provided buffer. The frozen `in_proj_a` shape leaves `u` untouched, as src/linear.h says.

## Numbers worth recording for the later tasks

* The forward is 2 GEMMs when frozen, 3 when adapted. Per layer at the plan's 8x1000 batch (N = 4200 tokens) one
  1024 -> 3584 projection is 4200 x 3584 x 1024 x 2 = 30.8 GFLOP, and its rank-16 pair is
  4200 x 16 x 1024 x 2 + 4200 x 3584 x 16 x 2 = 0.62 GFLOP, i.e. about 2% of the projection (design §5's table).
  A frozen `in_proj_a`-sized linear (1024 -> 16) is 4200 x 16 x 1024 x 2 = 0.14 GFLOP at that N: the same 1024
  multiply-accumulates per token, but only 16 outputs wide.
* The `u` temporary is `n * 16` floats; at N = 4200 that is 268,800 B, so `JT_FWD_ONLY` costs nothing measurable.
* rel error against the fp32/double-accumulation oracle at N = 4200 is 1.4e-06, so the layer-level gate of M4.3
  (`compare_layers.py --atol-rel 1e-3`) has about three orders of margin over the linear piece's own error, and the
  1e-5 gate here has a 7x margin.
