## The change (one file, `src/layer_gdn.c`)

The backward is design §4.8 in reverse, one already-tested call per step:

| step | call | shapes |
|---|---|---|
| `x_out = x_in + out_proj(y)`: `dres` (= dL/d(x_out) = dL/d(out)) is out_proj's `dy` | `linear_bwd(out_proj, f.y, f.uout, dres, n, dy, 0)` | n×1024×2048 |
| `y = GatedRMSNorm(o; gdn_norm, gate = z)` → `do`, `dz` | `gated_rmsnorm_bwd(f.o, gdn_norm, f.z, dy, f.ro, do, dz, n·16, 128, 0)` | |
| the recurrence, replayed from the fwd's checkpoints | `gdn_bwd(qkn, qkn+n2, ck+2n2, g, beta, do, off_dev, B, 16, n, nseg, ckpt, &gdn_work, dv, dq, dk, dg, dbeta)` | |
| `q = l2norm(qc)/√128`, `k = l2norm(kc)` | `l2norm_bwd(ck, dq, rq, 1/√128, dqc)` and `(ck+n2, dk, rk, 1, dkc)` | n·16×128 |
| `dc = concat(dqc, dkc, dv)`, `[3][n][2048]` → `[n][6144]` | `jt_from_head_major(dch, dcv, n, 3, 2048)` | |
| `cv = silu(pre)`, `pre = conv(qkv)` | `conv_bwd(dcv, f.pre, conv1d, row_of, off_dev, dqkv, n, 6144)` | |
| `beta = σ(bb)`, `g = -exp(A_log)·softplus(aa+dt_bias)` | `k_gdn_gates_bwd(dbeta, dg, beta, aa, a_log, dt_bias, dbb, daa, n·16, 16)` | |
| `da = dqkv W_qkv + dz W_z + dbb W_b + daa W_a` | `linear_bwd(in_proj_qkv, a, uqkv, dqkv, n, da, 0)` then `in_proj_z`, `in_proj_b`, `in_proj_a` with `accumulate_dx = 1` | n×1024×6144 … |
| `a = RMSNorm(x_in; input_layernorm)`, residual | `rmsnorm_bwd(x_in, input_norm, da, f.ra, dnorm, n, 1024, 1)` then `jt_add_inplace(dres, dnorm, n·1024)` | |

Decisions worth naming:

* **`dres` is read once and accumulated into at the end**, exactly as `src/layer.h` freezes it: it enters holding
  dL/d(x_out), is out_proj's `dy` (the residual adds `dL/d(out)` to the skip path's `dres`), and the input norm's `dx` is
  added to it (`jt_add_inplace`), never written over it. out_proj's `dx` therefore goes to a work buffer (`dy`), not to
  `dres`: `linear_bwd` reads `dy` in four of its five GEMMs, so `dx == dy` is already refused there.
* **`dv` needs no norm and no reassembly of its own**: `gdn_bwd` writes `dq/dk/dv` as `[N][H][128]`, which is the same
  memory as `[n][2048]`. `dq` and `dk` go through `l2norm_bwd` into the *pre-l2norm* (`dqc`, `dkc`) slots and `dv` is
  written straight into the third slot, so the `[3][n][2048]` buffer is `dc` and one `jt_from_head_major` turns it into
  the token-major `[n][6144]` that `conv_bwd` takes. (The forward's q|k|v split is the mirrored `jt_to_head_major`;
  `kernels/norm.h` and `kernels/gdn.h` both want contiguous `[n][2048]` slices, which is why both directions copy.)
* **`conv_bwd` gets `dc` (dL/d(cv)) and the saved `pre`**, not dL/d(pre): it applies silu's derivative itself and then
  the transposed causal conv, taps staying inside the token's row (design §4.8/§7).
* **One save list, walked by both halves.** The forward's save layout is now a single table (`walk()`), used by
  `bufs_get` (forward, from the front of the arena) and by `saves_replay` (backward, read-only from the arena's base). A
  permutation could otherwise pair a forward buffer with the wrong backward one. `saves_replay` also refuses to run when
  the save cursor holds fewer words than the layout needs, i.e. when the forward ran in `JT_FWD_ONLY` mode or for a
  different `n`: `layer_gdn: layer_gdn_mixer_bwd: the save half holds fewer floats than the mixer saves; did
  layer_gdn_mixer_fwd run in JT_FWD_SAVE mode for this n?`
* **`out_proj`'s `u` is now saved.** The forward called `linear_fwd(&lw->out_proj, f.y, n, f.out, NULL)`; out_proj *is*
  adapted (design §2.1), and `linear_bwd` needs `u` for both of its parameter GEMMs, so the forward now passes
  `save ? f.uout : NULL`. The forward's numbers do not change (u only feeds the `y += s u B^T` GEMM the forward already
  ran); the save block grows from 23,681 to **23,697 floats per token**.
* **Nothing allocated, nothing left behind**: the backward's 13 temporaries are **29,760 floats per token** from the
  arena's work half (`bwd_get`), given back with `jt_work_restore` before returning, so concatenated calls do not creep
  (the test checks the save cursor is unchanged after the call and prints the arena's free words). Saves + work =
  53,457 floats/token, inside `JT_ARENA_FLOATS_PER_TOKEN`'s 98,304.
* **Argument checks** (all `JT_LAYER_FAIL` with `layer_gdn: layer_gdn_mixer_bwd: <why>`): null ctx/lw/x_in/dres/b, `n !=
  b->n`, negative `n`, missing model / gradient buffer / frozen weight, and the save-cursor check above. An empty batch
  is `JT_LAYER_OK`. `bad()` now takes the function name, because this file has two entry points.

### 1. The driver (throwaway, gpubox only)

`test/test_layer.c` is J23's file and has no backward mode, so — as notes/J25.md and notes/J26.md did — the driver was a
**throwaway `test/test_j28.c` on gpubox only**, never in the worktree (`make nv`'s `test/test_*.c` wildcard builds it;

in exact mode:

1. `dL/d(post_mixer) = grad.layer.i.out + the MLP's path` (design §4.6), with the MLP walked by hand from the
   reference's own `layer.i.post_mixer` — `rmsnorm_fwd`, `linear_fwd` ×3 with their u's, `k_silu_mul_fwd`, then
   `linear_bwd(down)` + `k_silu_mul_bwd` + `linear_bwd(gate, up)` + `rmsnorm_bwd`. Its own six LoRA gradients are checked
   against the reference first, so a wrong hand-rolled MLP cannot smuggle a wrong `dy` past the gate.
2. `jt_saves_reset` + `layer_gdn_mixer_fwd(..., JT_FWD_SAVE)`; `layer.{i}.post_mixer` is checked at design §10.2's 1e-3
   (the saves and the reference's activations come from the same pass).
3. `lora_zero_grad`, then `layer_gdn_mixer_bwd(..., dres = dL/d(post_mixer))` → `dres` = dL/d(layer.i.in).
4. The gate at 5e-3: `dres` against `grad.layer.{i-1}.out` (i > 0) — for layer 0 against `grad.layer.0.in`, see below —
   and the six `grad.{stem}.lora_A/B` of `in_proj_qkv`, `in_proj_z`, `out_proj`. Plus: no gradient may appear outside
   those six pairs, and the save cursor must not have moved.

## Numbers worth recording for the later tasks

* **The exact chain and its GEMM shapes**: out_proj backward n×2048×1024 (+e, dB, dA), then the elementwise/row kernels,
  then `gdn_bwd` (the only heavy piece: 11.6 ms at B = 8 / N = 5094 per notes/J17.md), then `in_proj_qkv`
  n×1024×6144 + n×1024×16, `in_proj_z` n×1024×2048, and two n×1024×16 for the frozen `in_proj_a/b`. Per 107-token
  fixture the whole `test_j28` run (model load apart) is **0.59 s**.
* **Arena**: this layer's saves are **23,697 floats/token** (23,681 before out_proj's u was added) and its backward's
  work temporaries **29,760** (13 buffers, `bwd_get`); both halves are given back before returning (`arena free after the
  backward: 8061349 floats` on the fixture's 107-token ctx).
* **For M5.2 (`--dump-backward`)**: run `layer_fwd(i, …, JT_FWD_SAVE)` (which resets the save cursor itself) and then
  `layer_bwd(i, x_in, post_mixer, dres, …)`; this function reads saves from the arena's *base*, so `layer_fwd`'s split
  (mixer first, then MLP) is what makes the layout right. `dres` for layer i must come in as layer i+1's `dres` (the
  layer loop's "dx of layer i is the dy of layer i-1", design §6.2) and is not a dump key by itself — the key is
  `grad.layer.{i-1}.out`, which is exactly what the gate above compares.
* **For M5.4 (the card checkpoint)**: nothing new to run — `scripts/card-check.sh <A|B> m5` compares
  `grad.layer.{i}.out`, all 300 LoRA grads and `grad.readout` through `--dump-backward`. This layer's share of that gate
  should land at ~1e-06 in exact mode, i.e. the same as the per-layer numbers above; the only card-specific risk is
  `gdn_bwd`, already checked by G-m3.
* **`grad.layer.0.in`** has no key in `ref.safetensors`; the throwaway patched dump that adds it is described in 2 above
  (40 s on gpubox's CPU) if a later task wants a per-layer gate for layer 0 again.
