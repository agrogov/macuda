Decisions worth recording for the tasks that call these (M4/M5):

* **Naming.** `jt_` prefix, following J01's `jt_fill` and the `jt_*` namespace `test/harness.h`/`src/util.h` already use
  (the design's §8.1 example spells the wrappers `k_*`; the file that exists here wins). `jt_bf16_to_f32_n` carries the
  `_n` because `test/harness.h` owns the scalar helper `jt_bf16_to_f32(unsigned short)` — same widening, n elements at a
  time; a second function with that exact name would not compile in `test/k_misc.c`.
* **No CUDA in the reference.** `ref/misc.h` includes only `real.h`; `ref/misc.c` widens bf16 through a `uint32_t`
  copied into a `float`, so the double build (`-DJT_REAL_DOUBLE`) is exact too. The `_n` sweep and every copy op is
  dtype-agnostic, so `make test-cpu` builds it unchanged.
* **fwd `embed_gather` reads the bf16 table in place** (no 1 GB fp32 conversion of a 248320×1024 table).
* **Launch shapes.** grid-stride for the 1-D ops (`jt_grid_stride`, capped at 65535 blocks) and one block per token for
  `embed_gather`, exactly as design §8.1 says. The row-structured ops (`qgate_*`, `kv_*`, `to/from_head_major`) use one
  block per row (or per head) **strided over rows** instead of a flat grid-stride: inside a row the block walks heads and
  columns with `for` loops, so no thread ever divides an index, and the row over-strided grid means a large packed batch
  cannot overrun the grid's x limit. Same numbers, fewer integer divisions.
* **Every wrapper is a no-op for a zero dimension**, so no caller has to special-case an empty row slice.
* **Layout constants** (`JT_HIDDEN`, `JT_ATTN_HEADS 8`, `JT_ATTN_HEAD_DIM 256`, `JT_ATTN_KV_HEADS 2`,
  `JT_ATTN_KV_GROUP 4`, `JT_ATTN_Q_W 2048`, `JT_ATTN_QG_W 4096`, `JT_ATTN_KV_W 512`,
  `JT_ATTN_KV_EXPANDED_W 2048`, `JT_VOCAB 248320`) live in `kernels/misc.h` so that `model.c`, `layer_attn.c` and the
  tests agree. The wrappers take `heads`/`head_dim` as arguments; nothing is hard-coded inside a kernel.
* No backward refs: every op here is a copy/sum/gather, so `misc` has no `grad_*.c` (there is no `f(x)` with a
  differentiable input). Their correctness is pinned by comparing each against its own reference **and** by the two
  paired properties below, which a shared misunderstanding in `ref/` cannot fake.

## One warning found and fixed properly

gcc 13.3 on gpubox warned once (`-Wmaybe-uninitialized`, pointed at the ids buffer passed to `ref_embed_gather`) because
the compiler could not prove `n_tok > 0` on every path, so it saw a buffer that the fill loop might never have written.
Fixed by making the empty-shape contract explicit — every `t_*` case now returns early for a non-positive dimension,
which is also the contract the kernels have (`if (n == 0) return;` in each wrapper). Both builds are now warning-free
without touching the Makefile or the flags.
